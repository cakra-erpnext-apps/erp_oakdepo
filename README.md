# ERPOakDepo

Stack/bundle repository for the OakDepo ERPNext/Frappe deployment. The repo root *is*
the `container_depot` app repo — it gets bind-mounted as `apps/container_depot` in both
the dev and the prod stack, so a `git pull` here is the deploy unit.

This repo carries its own **self-contained stack** (compose project `erp_oakdepo_dev` /
`erp_oakdepo_prod`, image `oakdepo-erpnext:dev` / `:prod`). OakDepo no longer deploys from
the shared `cakra-erpnext-docker` multi-site stack — that split happened in 2026-07, and
the sibling `erp_cakra` repo runs its own `erp_oakglobal_prod` stack the same way.

It follows the same stack structure as `cakra-erpnext-apps/erp_cakra`, while keeping the
OakDepo app identity as `container_depot`.

## Components

| Path | What it is |
|---|---|
| `container_depot/` | The custom Frappe app — Container and ISO Tank Depot Management System. |
| `frontend/` | Vite source for the `/depot` ESS PWA. Build output (`container_depot/public/ess`, `container_depot/www/depot.html`) is gitignored and regenerated by `yarn build`. |
| `compose.dev.yaml` | Development stack. See [Development](#development). |
| `compose.prod.yaml` | Production stack. See [Production](#production). |
| `Dockerfile` | Bench image for both stacks; bakes every app in `apps.json` except `container_depot`. |
| `apps.json` | The bench apps baked into the image (erpnext, hrms, crm, helpdesk, raven, gameplan, telephony) with their pinned branches. |
| `.env.prod.example` | Template for `.env.prod`. Never commit the real one. |
| `ensure-apps.sh` | Boot wrapper: re-runs `pip install -e` for the bind-mounted app so a container recreate can't leave it uninstalled. |
| `nginx-inject.sh`, `nginx/`, `Caddyfile` | Reverse-proxy config; adds the SPA route for `/depot`. |
| `scripts/prod-update.sh` | The production update path. See [Production](#production). |
| `scripts/install-apps.py`, `scripts/patch-crm-assign-to.py` | Image build helpers — `install-apps.py` installs everything in `apps.json`; the CRM `assign_to` patch runs at build time *and* again on every prod update. |
| `STRUCTURE.md` | Repository coding and structure rules. |
| `BILLING_MODE.md`, `prd.md`, `docs/` | Domain and product notes. |

## Development

The dev stack is self-contained: it builds the image, creates the site, seeds it, builds
assets, and runs `bench start` (hot reload). Volumes are project-scoped, so it never
touches the prod stack.

```bash
docker compose -f compose.dev.yaml build
docker compose -f compose.dev.yaml up          # -d to detach
```

| | |
|---|---|
| Site | `oakdepo.localhost` (Administrator / `admin`) |
| Web | http://localhost:8000 |
| Socket.IO | port 9000 |
| MariaDB | port 3306, root password `123` — exposed for local DB tooling; prod keeps it internal |

Override with `SITE_NAME`, `ADMIN_PASS`, `DB_ROOT_PASS` if needed.

**First boot is slow and that is expected.** `create-site` installs all nine apps, then
`frappe` builds bench assets in batches (building crm/helpdesk/gameplan together OOM-kills
a normal dev box) and runs `yarn build` for the PWA. Subsequent starts skip both via the
`.dev-assets-built` marker and the presence of `www/depot.html`.

`create-site` also runs `container_depot.dev_setup.run`, which completes the ERPNext setup
wizard (company **Oak Depo** / **OD**, Indonesia, IDR, Asia/Jakarta) and seeds depot
masters — Branch, Depot OAK1/OAK2/OAKSBY, items, checklist rows, damage/repair codes,
cargo, customers. Both halves are idempotent; `container_depot.seed_dev.clear` undoes the
seeding half. **Never run either against prod.**

### Everyday bench commands

Run from this directory. `bench` is not installed on the host — it only exists in the
container.

```bash
# Migrate (sync doctype JSON + patches + after_migrate hooks)
docker compose -f compose.dev.yaml exec -T frappe \
  bash -lc 'bench --site oakdepo.localhost migrate'

# App test suite
docker compose -f compose.dev.yaml exec -T frappe \
  bash -lc 'bench --site oakdepo.localhost run-tests --app container_depot'

# Arbitrary code
docker compose -f compose.dev.yaml exec -T frappe \
  bash -lc 'bench --site oakdepo.localhost execute <dotted.path> --kwargs "{...}"'
```

> **Test trap:** on a site without `allow_tests`, `run-tests` prints *"Testing is disabled
> for the site!"* and **exits 0 without running anything**. `create-site` sets the flag, so
> a stack-created site is fine — but never read a 0 exit as passing. Check the test count.

### Reset

```bash
docker compose -f compose.dev.yaml down -v    # drops site, DB, and assets; next up re-seeds
```

## Local app install inside an existing bench

If you already have a bench and only want the app:

```bash
cd /home/frappe/frappe-bench
bench get-app container_depot <path_to_this_repo>
bench --site <site> install-app container_depot
bench --site <site> migrate
```

## Production

Site `app.oakdepo.com`, deployed from `/home/apps/erp_oakdepo/erp_oakdepo` on the server,
compose project `erp_oakdepo_prod`.

### Routine updates

Use the script — do not hand-run `docker compose up`. It sequences steps that break the
site when done out of order:

```bash
cd /home/apps/erp_oakdepo/erp_oakdepo
./scripts/prod-update.sh
```

It runs: `git pull` → recreate app containers → rewrite `sites/apps.txt` + `pip install -e`
→ CRM `assign_to` patch → **site backup** → `bench migrate` → batched `bench build` → PWA
`yarn build` (in a throwaway `node:20` container) → materialize `sites/assets` for nginx →
clear cache → restart → verify with an HTTPS probe and `list-apps`.

The asset materialize step is not optional: the nginx container cannot follow bench's
asset symlinks, so the built files have to be physically copied.

| Variable | Default | Use |
|---|---|---|
| `BUILD_IMAGE` | `0` | Set to `1` when the `Dockerfile` or `apps.json` changed. |
| `SKIP_GIT_PULL` | `0` | Set to `1` to deploy the working tree as-is. |
| `SITE` | `app.oakdepo.com` | |
| `IMAGE` | `oakdepo-erpnext:prod` | |

### First boot / manual operations

```bash
cp .env.prod.example .env.prod
# edit .env.prod with real values; do not commit it

docker compose --env-file .env.prod -f compose.prod.yaml config    # validate
docker compose --env-file .env.prod -f compose.prod.yaml up -d
```

Ad-hoc backup before any manual production change:

```bash
docker compose --env-file .env.prod -f compose.prod.yaml exec backend \
  bench --site "$SITE_NAME" backup
```

## Deploying the role model (2026-08-06 release)

This release seeds 13 roles, rewrites the permission matrix, and **deletes five
Notification records** that duplicated the app's own events. Back up first — with this
one the backup is not optional.

`scripts/prod-update.sh` already covers the pull, PWA rebuild, backup, and migrate. If you
are running the steps by hand instead:

```bash
# 1. Pull + rebuild the PWA bundle (menu gating lives in the built assets)
git pull
docker compose --env-file .env.prod -f compose.prod.yaml exec backend \
  bash -lc 'cd apps/container_depot/frontend && yarn build'

# 2. Migrate. Seeds the roles, the permission matrix, and 19 notification rules;
#    patch v0_51 removes the duplicate Notifications. Idempotent — safe to re-run.
docker compose --env-file .env.prod -f compose.prod.yaml exec backend \
  bench --site "$SITE_NAME" migrate

# 3. Verify
docker compose --env-file .env.prod -f compose.prod.yaml exec backend \
  bench --site "$SITE_NAME" execute frappe.client.get_list \
  --kwargs "{'doctype':'Role','filters':{'is_depot_field_role':1},'fields':['name','desk_access']}"
```

**Then assign roles — nothing happens until you do.** No existing user holds any of the
new roles, so every non-System-Manager account opens `/depot` to an empty state until an
admin assigns one. Assignment is a single **Role Profile** per user — one profile per app
role, and the office ones bundle their companion ERPNext role so it cannot be forgotten.
Procedure (which profile, branch scoping, and what a profile does to a user's other roles)
is in `STRUCTURE.md § Role model → Assigning a user`.

Post-deploy admin screens live under **Container Depot → Notifikasi & Akses**:

| Screen | Use |
|---|---|
| Depot Notification Rule | Change who receives an event. Takes effect immediately, no deploy. |
| Depot Notification Settings | Master switch (turn all depot notifications off during maintenance) + fallback roles. |
| Role | Tick *Depot Field Role (PWA)* to let a new role into `/depot`. |
